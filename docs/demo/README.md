# docs/demo — the screenshots, and what to capture

This folder is the fallback in [DEMO.md](../../DEMO.md): *"Laptop dies: the screenshots
in `docs/demo/` on a second machine, narrated."* It holds no screenshots yet. Fill it at
the rehearsal, from a machine that is already set up for the demo — the point of taking
them then rather than earlier is that they show the build the class will see, at the
window size the projector will use.

Nothing in the app reads this folder. If it stays empty the demo still runs; the only
thing lost is the answer to a dead laptop.

## How to take them

Server on `--port 8001`, seeded profile, browser at the demo's own window size and zoom
(the *Demo day* checklist in DEMO.md sets both). Sign in as `maya` first — every screen
below except the first two needs that cookie, and an untailored screenshot of a tailored
card is worse than none, because it is the state the presenter will be describing.

Full-page captures, PNG, named as below so they sort into the running order. Every URL is
in DEMO.md under *The URLs, in order*; none of them is repeated here, so there is one
place to fix if a link changes.

ending appears, and `/profile` for a signed-in reader, which is the only screen showing
the shortlist controls. Number them `11-` and `12-`.

## What to check while you are there

Taking the screenshots is also the last read-through of the demo. Note anything where
the copy on screen contradicts what the presenter is about to say, and put it on the
rehearsal list rather than fixing it at midnight:

- every figure the script quotes out loud appears on the screen it is quoted from;
- the tailored cards say *Tailored to you* on all three, and none of Maya's answers is
  visible in the address bar;
- the trend at 2015–2021 draws no coverage notice, and the same card at 2015–2024 draws
  exactly one, naming no school;
- the browser console is empty on the sign-up form.
